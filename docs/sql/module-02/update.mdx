---
title: Update - UPDATE
description: Modify existing rows safely with UPDATE and WHERE.
---

<Code>UPDATE</Code> modifies existing rows in a table. Always pair it with <Code>WHERE</Code> — leave that off and it changes **every row** in the table.

---

## Basic syntax

```sql title="example.sql"
UPDATE table_name
SET column = value
WHERE condition;
```

- <Code>UPDATE</Code> — which table to modify
- <Code>SET</Code> — the new value(s)
- <Code>WHERE</Code> — which rows to apply it to

---

## Updating one row

```sql title="example.sql"
UPDATE books
SET price = 11.99
WHERE title = 'Dune';
```

## Updating multiple columns at once

Separate each column with a comma:

```sql title="example.sql"
UPDATE books
SET price = 8.99, in_stock = FALSE
WHERE title = '1984';
```

---

## Updating multiple rows

<Code>WHERE</Code> can match more than one row — every matching row gets updated:

```sql title="example.sql"
UPDATE books
SET in_stock = FALSE
WHERE price > 15;
```

---

## The most important rule

Forgetting <Code>WHERE</Code> updates the entire table:

```sql title="example.sql"
-- Danger: this sets EVERY book's price to 0
UPDATE books
SET price = 0;
```

There's no built-in undo once this runs (unless you're inside a transaction — covered in Module 03).

---

## Preview before you update

Run the same condition as a <Code>SELECT</Code> first, to see exactly which rows will be affected:

```sql title="example.sql"
SELECT * FROM books WHERE title = 'Dune';
```

If that returns the rows you expect, swap it for the <Code>UPDATE</Code> with confidence.

---

## MySQL's safety net

MySQL's "safe update mode" can block an <Code>UPDATE</Code> that doesn't use a key column in <Code>WHERE</Code>, throwing **Error 1175**. If you hit this, it's protecting you from an accidental mass update — not a bug.
