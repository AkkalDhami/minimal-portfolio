Normalization is a core concept in Database design that helps you organize data efficiently in a relational database. The goal is to reduce redundancy (duplicate data) and improve data integrity (accuracy and consistency).

<br />
---
<br />

## 1. What is Normalization?

Normalization is the process of structuring a database so that:

- Each piece of data is stored only once
- Relationships between data are clearly defined
- Updates, inserts, and deletes don't create inconsistencies


<br />
---
<br />


## 2. Why is Normalization Important?

Normalization is important because it helps maintain a database that is efficient, consistent, and easy to manage.

- **Reduces Data Redundancy:** Imagine storing a customer's address every time they place an order. If the address changes, you'd have to update it in multiple places! Normalization helps you store information in one place and refer to it from other places, minimizing repetition.
- **Improves Data Integrity:** Less redundancy means less chance of inconsistencies. If you update an address in one place, it's updated everywhere it's needed.
- **Prevents Anomalies:** Normalization helps prevent issues like:
    - **Insertion Anomalies:** Difficulty adding new data because you're missing related information.
    - **Update Anomalies:** Having to update the same information in multiple rows.
    - **Deletion Anomalies:** Accidentally losing valuable information when you delete something seemingly unrelated.
- **Easier to Understand and Maintain:** A normalized database is generally more logically structured and easier to understand, query, and modify.

## 3. First Normal Form (1NF): Atomic Values


- All columns contain <Highlight>atomic</Highlight> values (i.e., indivisible values).
- Each row is <Highlight>unique</Highlight> (i.e., no duplicate rows).
- Each column has a unique name.

## 4. Second Normal Form (2NF): Remove Partial Dependencies

- Must already be in <Highlight>1NF</Highlight>
- No partial dependency (non-key attributes depend on only part of a <Highlight>composite key</Highlight>)

> Every non-key column must depend on the whole primary key.

**Assume:**
- <Highlight>Primary Key</Highlight> = (StudentID, Course)

## 5. Third Normal Form (3NF): Remove Transitive Dependencies

- Must already be in <Highlight>2NF</Highlight>
- No <Highlight>transitive dependency</Highlight> (non-key attributes depend on other non-key attributes)

##### Suppose we have:

<Table>
<THead>
  <TR>
      <TD>StudentID</TD>
      <TD>DepartmentID</TD>
      <TD>DepartmentName</TD>
  </TR>
</THead>
<TBody>
<TR>
  <TD>1001</TD>
  <TD>D1</TD>
  <TD>Computer Science</TD>
</TR>
<TR>
  <TD>1002</TD>
  <TD>D2</TD>
  <TD>Electronics</TD>
</TR>
</TBody>
</Table>


Here:

<Output>
StudentID → DepartmentID
DepartmentID → DepartmentName
</Output>

Therefore:
<Output>
StudentID → DepartmentName
</Output>

**This is a transitive dependency.**

</TR>
<TR>
<TD>1002</TD>
<TD>D2</TD>
</TR>
</TBody>
</Table>

**Departments:**


<Table>

## 6. Boyce-Codd Normal Form (BCNF): Stronger Version of 3NF

- A stricter version of <Highlight>3NF</Highlight>
- Every determinant must be a <Highlight>candidate</Highlight> key

##### Example

##### A university has:

<Table>
<THead>
<TR>
<TD>Teacher</TD>
<TD>Subject</TD>
<TD>Room</TD>
</TR>
</THead>
<TBody>
<TR>
<TD>Smith</TD>
<TD>DBMS</TD>
<TD>R101</TD>
</TR>
<TR>
<TD>Smith</TD>
<TD>OS</TD>
<TD>R101</TD>
</TR>
<TR>
<TD>Jones</TD>
<TD>CN</TD>
<TD>R102</TD>
</TR>
</TBody>
</Table>


**Rules:**
<Output>
Teacher → Room
Subject → Teacher
</Output>

**Candidate Keys:** <Highlight>Subject</Highlight> because a subject has one teacher.

##### Problem

**Teacher** determines **Room**, but **Teacher** is not a **candidate** key.

This violates <Highlight>BCNF</Highlight>.

**Teachers:**

</TR>
<TR>
<TD>Jones</TD>
<TD>R102</TD>
</TR>
</TBody>
</Table>

**Courses:**

<THead>
<TR>
<TD>Subject</TD>
<TD>Teacher</TD>
</TR>
</THead>

## 7. Normalization Summary

<Table>
  <THead>
    <TR>
      <TD>Normal Form</TD>
      <TD>Goal</TD>
      <TD>Problem Solved</TD>
    </TR>
  </THead>
  <TBody>
    <TR>
      <TD>1NF</TD>
      <TD>Ensure all attributes contain atomic (single) values</TD>
      <TD>Removes repeating groups and multi-valued attributes</TD>
    </TR>
    <TR>
      <TD>2NF</TD>
      <TD>Ensure non-key attributes depend on the entire primary key</TD>
      <TD>Removes partial dependencies</TD>
    </TR>
    <TR>
      <TD>3NF</TD>
      <TD>Ensure non-key attributes depend only on the key</TD>
      <TD>Removes transitive dependencies</TD>
    </TR>
    <TR>
      <TD>BCNF</TD>
      <TD>Ensure every determinant is a candidate key</TD>
      <TD>Removes remaining anomalies not handled by 3NF</TD>
    </TR>
  </TBody>
</Table>


<Note text="Normalization is the process of organizing data in a database to reduce redundancy, eliminate data anomalies, and improve data integrity by dividing data into related tables and defining proper relationships between them."/>
